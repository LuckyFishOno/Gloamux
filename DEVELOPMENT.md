# Gloamux development guide

[English](DEVELOPMENT.md) · [繁體中文](DEVELOPMENT.zh-TW.md)

## Source layout

The Swift package lives in [Gloamux](Gloamux). The `GloamuxApp` executable launches the native macOS interface and also runs as the `gloamux` command line. `GloamuxShared` holds the feature contract every module implements. `Sources/app` manages the session tree, windows, tabs, preferences, and credential vault. Interface text lives in `Sources/app/Resources/<language>.lproj/Localizable.strings`, keyed by the English source string. The catalogs are `en`, `zh-Hant`, `zh-Hans`, `ja`, and `es`. Add new `T("…")` strings to every catalog. `TerminalInputTests` checks that the catalogs have the same keys. The language choice is stored as the app's `AppleLanguages` preference, the same value as the per-app language in System Settings, and `package-app.sh` declares the shipped languages in `CFBundleLocalizations`. The `terminal` and `LocalPTY` targets handle terminal state and the local login shell. The `ssh`, `network` (module `GloamuxNetwork`, so it does not hide Apple's `Network` framework from `AppIntents` and other system modules), and `file-transfer` targets implement remote sessions and SFTP. `Sources/intents` (module `ShellIntents`) holds the App Intents for Shortcuts and depends on nothing else in the package.

The packaging script builds an optimized release app bundle, `build/Gloamux.app`, by default. Debug builds parse and draw terminal output several times slower, so use the packaged app to judge responsiveness. To use a different build cache or destination, pass them as the first and second arguments to `package-app.sh`.

UI explanations go behind an `InfoButton` (the "!" popover, an AppKit `NSPopover` so it opens without redrawing the SwiftUI views around it), not caption paragraphs. Keep labels short; where a translation is longer, let the label wrap with `.fixedSize(horizontal: false, vertical: true)` instead of truncating it.

Use [Humanizer-zh](https://github.com/op7418/Humanizer-zh/blob/main/SKILL.md) when editing the Traditional Chinese interface and the `.zh-TW.md` documents. Each English document has a Traditional Chinese copy; update both together. Use the same terms for the same action, and keep the original conditions, format placeholders, and command examples.

SwiftPM currently warns about conflicting `swift-nio-ssh` and `swift-nio-ssl` package identities. Gloamux uses the [vendored swift-nio-ssh](Gloamux/Vendor/swift-nio-ssh/VENDORED.md) for agent and X11 forwarding, and the [vendored swift-nio-ssl](Gloamux/Vendor/swift-nio-ssl/VENDORED.md) for FTPS TLS session reuse. Citadel and swift-nio-extras declare the same package identities through their upstream URLs. SwiftPM uses the local checkout for this build, so the identity warning is expected and can be ignored with the current toolchain. Recheck resolution when upgrading SwiftPM because future versions may make this conflict an error.

## Local data

Gloamux stores its working files under `~/Library/Application Support/Gloamux`. Everything uses the name Gloamux: the GitHub repository, the app (`Gloamux.app`, bundle ID `local.gloamux.desktop`), the data folder, the `gloamux` command, `gloamux://` links, and the interface text. The app bundle also links `gloam` to the same executable as a short command name; `main.swift` treats both names as the CLI. Gloamux was called Termac, and MShell before that: unless `--workspace` is passed, `LegacyName.migrate` moves the newest earlier folder (`Termac`, then `MShell`) there when the Gloamux folder does not exist yet, and copies the newest earlier settings (`local.termac.desktop`, then `local.mshell.desktop`) when `local.gloamux.desktop` has none. It does nothing while an earlier app is running. Exports with the earlier extensions and format names still import. The session catalog stores connection settings and key-file paths. Host fingerprints, saved sign-ins (`saved-sign-ins.json`), and the optional encrypted password vault have separate data files. Quick commands are stored as plain text in `quick-commands.json`. Keep secrets out of saved commands. For UI checks, pass `--workspace /path/to/test-workspace` to the app executable to isolate these files from your regular workspace.

The layout menu in the toolbar and the `gloamux layout` command both set the `layout.json` preference. The menu applies the layout at once, and so does a CLI change while the app is open; otherwise the next launch uses it. `layout set` takes `default`, `classic`, and `workbench`, which are stored as `macos`, `terminal`, and `transfer`; earlier names such as `xshell` and `mobaxterm` still work. Pass `--workspace PATH` at the end of a layout command to target an isolated workspace. The Classic and Workbench chrome lives in `ClassicLayouts.swift`, and its model support (address bar, compose bar, folder following, host monitoring) lives in `ClassicWorkspace.swift`.

Each item in `sessions.json` may carry an `order` once the user drags items into place. `SessionTreeStore.children(of:)` lists ordered items first, then unordered ones folders first and by name, so older catalogs keep their order. `drop(_:on:_:)` applies a drag and renumbers that folder by the custom order even while the tree is sorted by name. The catalog's optional `sorting` field (`nameAscending` or `nameDescending`; absent means custom) picks how `children(of:)` lists items. File transfers go through `TransferQueue`, which `WorkspaceModel.transfers` shares between the file sidebar (`RemoteFileSidebar`, which shows `LocalTreeState` for the local terminal), the two-pane `FileTransferView`, and every layout. The Default layout shows `FileTransferView` in the main window when `workspaceMode` is `.files`, following the selected tab. The Classic and Workbench layouts show it in `FileTransferWindow` with a server menu. It runs one item at a time on the tab's SFTP channel. Uploads write a temporary `.name.gloamux-….partial` file and rename it into place. Downloads write a hidden partial file beside the destination. `SFTPTransfer` keeps 16 reads or writes of 32 KiB in flight and stops at task cancellation. Saved forwarding rules are stored with the connection in `sessions.json`. Local and dynamic forwards listen on this Mac's loopback interface. Reverse forwards ask the server to listen on its loopback interface. Enter a fixed listening port or leave it blank for an automatically assigned port.

The vault keeps its Touch ID unlock material in memory with Secure Enclave protection. A new app process requires the master password. Gloamux's Secure Enclave SSH key lives in the storage folder as `ssh-key-secure-enclave` (see `AppSSHKey`). It holds a sealed representation that only this Mac can use. New keys sign without Touch ID. Older keys that require it ask once per launch while the key loads, before the SSH handshake, so signing on the connection's event loop never waits for the user. Where passwords that sign in go depends on whether a vault exists. Without one, passwords and key passphrases that sign in are saved by `CredentialVault.rememberWorking` to `DeviceSecrets`: AES-GCM entries, with the entry ID as associated data, under a key rebuilt from a Secure Enclave key agreement that needs no Touch ID. They work after a restart without the master password. Passphrases use the entry ID `passphrase:<key path>`. Without a Secure Enclave, secrets go to the master-password vault as before. `DeviceSecrets` stays on after the vault is created, so a locked vault does not stop sessions from connecting. While the vault is unlocked, `connect` skips the per-session `confirmsEachConnection` check; while it is locked, that check runs. When only the locked vault holds a needed secret (`CredentialVault.lockedVaultIDs`) and Touch ID is set up for this launch, `readWithTouchID` reads those entries into `sessionPasswords` without unlocking the vault, and that prompt stands in for the per-session check. Tests replace the prompt with `enableTouchIDForTesting`. New sessions start with that check on. **Add to vault** (`CredentialVault.addToVault`) saves a password before it signs in. `SavedSignInsView` lists both places (`CredentialVault.Place`), and reveals, copies, or deletes one copy after `WorkspaceModel.authorizeSavedSignIns`. Removing a key calls `forgetRemembered`, which deletes the copy on this Mac and, while unlocked, the vault copy. A session with `confirmsEachConnection` calls `WorkspaceModel.confirmOwner` (Touch ID or the Mac password) before it uses a saved secret.

## Shell integration and terminal tools

`TerminalScreen` (in `Sources/terminal`) records OSC 133 marks as `CommandMark`s with absolute line numbers (`trimmedLines` plus the scrollback index, so marks survive trimming) and raises `TerminalEvent.commandFinished`. OSC 8 links go into a link table, and each `CellStyle` keeps a link index that SGR 0 does not clear. OSC 7 sets `workingDirectory`. Local zsh loads the marks through `ZDOTDIR` pointing at a generated `.zshenv` in the user's temporary folder (`ShellIntegration.zshDirectory()`); it restores the user's `ZDOTDIR` and adds its hooks after the user's own on the first prompt. Other shells and SSH sessions get the one-line `ShellIntegration.hook`, typed on request, or automatically for SSH when **Settings › Terminal** says so. Local processes start through `gloamux_spawn_command` in `LocalPTY.c`, which takes an argument vector and extra environment; container sessions run `docker`, `kubectl`, or `aws ssm start-session` through the login shell (`LocalLaunch.command`).

Every terminal's output goes through `WorkspaceModel.terminalReceived`, which feeds the screen, the recorder, and command observers. A finished command that ran at least the notification threshold in a tab that is not visible sets `attention` on it and posts a notification when Gloamux runs as an app bundle. Runbooks (`Runbooks.swift`, Markdown in `runbooks/` in the workspace folder) send one block at a time as a bracketed paste, wait for its `commandFinished`, stop at the first failure, and save results in `runbooks/.results/`. Recordings (`TerminalRecording.swift`) keep output only, pass it through `SecretRedaction` (which also finds secrets split across chunks) when saving, and write asciicast v2 files to `recordings/` with mode 0600.

Environment tags live on `SessionTreeNode.environment`; sessions inherit them from folders (`effectiveEnvironment`). In the environments chosen in **Settings › Safety**, `typeTerminal` holds a line that matches `RiskyCommands.patterns` until the pane's alert is answered. The line comes from the screen after the OSC 133 B mark when the shell reports one, otherwise from what was typed.

The menu bar item, the command palette (`CommandPalette.swift`), Spotlight (`SpotlightIndex`, names and addresses only), the `gloamux://open?id=` and `gloamux://new-terminal` links, and the Shortcuts actions all call the same `WorkspaceModel` operations. `package-app.sh` runs `appintentsmetadataprocessor` on the constant values SwiftPM emits for `ShellIntents` to write `Metadata.appintents`; without it the app works but Shortcuts lists no Gloamux actions. Reachability dots come from a non-blocking TCP connect to each visible saved host's SSH port, at most six at a time, every 90 seconds; sessions through a proxy, a jump host, or a container are not checked. Host key decisions are appended to `host-key-history.json` (2,000 entries at most).

Remote Quick Look copies one file of at most 100 MB into a private temporary folder and deletes it with the next preview and at quit.

## Terminal view

`TerminalDisplay` draws the scrollback and screen as attributed lines in an `NSTextView` (`TerminalTextView`) and replaces only the lines that changed. Cells on the default background carry no background color, so the view's own color, which can be translucent over `TerminalBackdrop` (a behind-window `NSVisualEffectView`), shows through. The cursor is a separate `TerminalCursorView` over its cell: changing its shape, focus, or blink never redraws a line, and blinking is a Core Animation keyframe animation. Input method composition is kept in the view and drawn over the cursor; it never enters the text storage, and while it is active every key goes to the input method. The find bar searches the text storage and marks matches with layout-manager temporary attributes; while the bar is open, new output is searched again after 0.2 s.

`TerminalScreen` tracks the mouse modes a program sets (1000, 1002, 1003, with SGR coordinates for 1006), focus reports (1004), DECSCUSR cursor shapes, and OSC 52 clipboard writes, which `terminalReceived` applies only when **Settings › Terminal** allows them. A session in another encoding is converted to UTF-8 by `TerminalDecoder` before parsing, and input is converted back in `enqueueTerminalInput`; the encoding is saved on the session (`SavedConnection.encoding`). Terminal settings use the `Gloamux.terminal.*` keys in `TerminalPreferences`. Session logs (`TerminalLogs`) go to `logs/` in the workspace folder with mode 0600, masked line by line with `SecretRedaction`.

## Performance

`gloamux benchmark [--megabytes N] [--columns N] [--rows N] [--json]` feeds plain text, colored logs, CJK text, full-screen redraws, and OSC 133 prompts through `TerminalScreen` in 4 KB reads, times a full redraw of the visible lines with `TerminalLineRenderer`, and times one keystroke's echo. Run it from the packaged release app. On an Apple silicon Mac at 160×48 (November 22, 2026): plain text about 100 MB/s, colored logs 36 MB/s, CJK 20 MB/s, full-screen redraws 25 MB/s, OSC 133 prompts 10 MB/s; a full redraw takes 0.4–0.7 ms; a keystroke echo takes about 0.01 ms.

**Stress test.** `python3 Gloamux/scripts/stress-test.py` drives the packaged app through `gloamux` and `gloamux mcp` under load and records what it costs the Mac. It needs only the Python 3 standard library and macOS's OpenSSH, so an agent such as Codex or Claude Code can run it unattended after `Gloamux/scripts/package-app.sh`. It creates a throwaway workspace and a throwaway `sshd` on 127.0.0.1 that accepts only a key made for the run. It never opens your workspace, never signs in with a password, and never connects to another host. The app it starts is a separate process that it quits at the end. In that workspace only, it turns on agent access for the test session, as a user would in Settings › Agents.

It covers these areas:

- the session catalog with the app closed and open
- configuration export and import, including a damaged backup that must be refused
- SFTP and SCP transfers of large files, and recursive folder transfers
- SSH connection churn, sequential and parallel
- `gloamux benchmark`
- 20 local and 10 SSH tabs, each printing a million lines
- port forwarding, checked with a TCP echo server
- every MCP tool, including that an agent sees only allowed sessions and that a proposed command waits for review

Each phase gets a pass or fail, its own figures, the app's CPU time and peak memory, and the CPU used by the CLI processes it ran.

Options: `--quick` runs about a fifth of the load, `--no-app` skips the phases that need the app, `--out DIR` chooses the report folder, and `--keep` keeps the throwaway files. The report is written as `report.md` and `report.json`, with once-a-second samples in `samples.csv`. The exit status is 0 when every phase passed, 1 when any failed, and 2 for a setup problem.

Memory figures are the physical footprint shown in Activity Monitor. RSS is also recorded, but it stays high after memory is freed. A full run on an Apple silicon Mac (10 cores, November 22, 2026) gave these results:

- The app was idle at 93 MB and peaked at about 1 GB with the 30 busy tabs. A tab with a full 5,000-line scrollback at 160 columns holds about 33 MB.
- The tabs printed about 560,000 lines a second in total.
- Agent and CLI requests to the running app took 4 ms and 13 ms.
- SFTP moved about 1 GB/s up and 730 MB/s down, and a forwarded port carried about 800 MB/s.
- After the tabs closed, 36 MB was still in use in the heap. The footprint stayed near 390 MB because the allocator keeps freed pages for reuse.

SwiftUI holds the values it last drew until it draws again, so closed tabs are released at the window's next update.

Terminal output is flow-controlled:

- **SSH shells.** Above 64 unread chunks, an SSH shell stops reading its channel. The SSH window then fills and the server waits.
- **Local shells.** Output reaches the screen through `TerminalOutputPump` in order, in batches. Above 1 MB waiting, the PTY read source is suspended until the screen catches up.

**Metal.** Building every visible line takes under 1 ms, and AppKit then draws only the lines that changed, so a Metal renderer would not change what users notice today. The parser is the limit. Runs of printable ASCII are now written a row at a time, UTF-8 is decoded without a `String` per character, and CSI parameters are parsed byte by byte. CJK text still goes through the width lookup one character at a time, so that is the next place to speed up before considering a glyph-atlas Metal renderer.

**Inline images.** iTerm2's `OSC 1337 File=` and the kitty graphics protocol carry PNG or raw pixels that `NSImage` and `CGImage` decode directly, so they fit the current text view as attachments anchored to cells; sixel needs its own decoder. If added: iTerm2 first, then kitty's direct transmission (not its file or shared-memory modes), then sixel; cap each image at 10 MB encoded and 4096×4096 pixels, and keep at most 64 MB of decoded images per tab, dropped as their lines leave the scrollback. Images from a remote host must never read local files.

## File protocols and display connections

`RemoteFileSystem` is shared by the browser, queue, previews, and CLI. SSH defaults to SFTP and falls back to SCP after a subsystem refusal. Profiles can force either protocol. FTP uses passive data connections. Explicit and implicit FTPS encrypt both connections, reuse the control connection's TLS session on the data connection, and use system trust or a verified certificate pin. CLI uploads stage content at a temporary remote name before renaming. OpenSSH SFTP replacement uses the advertised `posix-rename@openssh.com` extension.

The `gloamux` product shares the app executable. `WorkspaceCommand` dispatches management operations. `gloamux xserver` is the exception: it checks and starts XQuartz in the CLI process through `XQuartz`, since XQuartz belongs to the Mac rather than a workspace. `WorkspaceCommandChannel` serializes workspace writers and routes requests to the active app window over a private same-user channel. File commands open their own authenticated transport and keep supplied passwords and one-time host fingerprints in memory. While a newer CLI is editing a workspace, use the current packaged app for that same workspace.

The optional X11 setting applies only to the SSH shell. `SSHX11Configuration` gets the local display from `DISPLAY` or launchd and reads its MIT-MAGIC-COOKIE-1 authorization using XQuartz's `xauth`. Gloamux sends a randomly generated substitute in the SSH request, validates the X11 setup before opening a local connection, and replaces the substitute in memory. Only a local socket or loopback endpoint is allowed. Closing the shell closes its X11 channels. The tests use a loopback SSH server and a fake display and can run without XQuartz.

RDP and VNC open in Gloamux's remote desktop tabs. `RemoteDesktopPane` draws the latest frame, scales it to the pane, and translates keyboard and pointer events. The packaging script builds the locked Rust project in `Gloamux/RDP` and signs the helper in `Contents/Helpers`. Rust 1.94 or later and Cargo are required to package the app. The bundled helper runs for one connection and exchanges sign-in data, input, and frames with Swift through private pipes. Closing the tab ends the process.

The Default layout's toolbar switches between File Transfer and Terminal. A new connection tab can start with SSH, RDP, or VNC. Choosing a desktop protocol replaces the terminal connection form in that tab. The connection tree opens a compact editor where a saved desktop profile can switch between RDP and VNC. A certificate pin is retained only for the same RDP endpoint.

MultiExec (`WorkspaceModel.multiExec`) belongs to one window: `typeTerminal` sends input to every ready terminal of that window, including tabs moved to their own windows, and skips read-only ones and remote desktops; risky-command checks still apply to each target. The Tunnels window and `gloamux forwards live-list` share `WorkspaceModel.tunnelTabs`, which lists only connected SSH tabs, because a tab that is not connected shows the new-connection form.

Workspace windows have independent models and tabs. They share the saved session catalog, vault, known hosts, quick commands, recents, and runbooks. A new window starts with a local terminal. The first window owns the saved-tab snapshot. Closing a workspace cleans up its sessions and tool windows, and closing the last workspace quits the app.

RDP uses IronRDP for NLA with NTLM and TLS. A server certificate must pass system verification or match the SHA-256 fingerprint explicitly approved for that saved profile. Compare the displayed fingerprint with the server's certificate before approving it. VNC supports RFB 3.3, 3.7, and 3.8, and answers newer servers such as macOS (3.889) as 3.8. It requests ZRLE, CopyRect, and raw rectangles plus server resize messages, and keeps one zlib stream for the connection as ZRLE requires. Sign-in uses no authentication, the classic VNC password, or Apple Remote Desktop (security type 30) when a user name is entered. Type 30 is what macOS Screen Sharing uses for a Mac account: a Diffie-Hellman exchange keys AES-128 for the account name and password. Only the credentials are encrypted. The rest of the VNC traffic is not. RDP follows the pane size by default. A connection can instead fix a resolution (`DesktopResolution` presets, at most 2560 × 1600), ask for Retina, which sends twice the pixels with a 200% desktop scale, and pick a quality, which `rdp.rs` `quality()` maps to the connection type and performance flags. Clipboard sharing follows the connection, or the `desktop.share-clipboard` default when the connection leaves it unset. RDP gateways, and redirected drives, printers, smart cards, audio, and cameras are outside the current desktop implementation; an SSH tunnel (Through SSH) is the supported way to reach a desktop behind a server.

## Tests

Run `swift test --package-path Gloamux` from the repository root. `ReflowTests` covers rewrapping on resize, splitting output at any byte, and CSI parameter parsing. `TerminalModesTests` covers mouse and focus reports, cursor shapes, OSC 52, scrollback size, and legacy encodings. `TerminalViewBehaviorTests` covers input method composition, find, mouse reports, and the cursor in a real window. `TerminalFeaturesTests` covers redaction, asciicast files, runbook parsing, risky commands, environments, container command lines, discovery parsers, host key history, palette search, the URL scheme, reachability probes, and the benchmark workloads. SSH and forwarding integration tests use loopback fixtures. SFTP tests also use macOS's `sftp-server`. The test suite exercises separate host-key approvals for the destination and jump host, transfer round trips, reconnect after transport loss, and independent local terminals.

Optional format compatibility tests read from the directory specified by `XSHELL_DIR`. The original Xshell installation and fixtures are external test inputs.

`RemoteKindsTests` checks that saved desktop profiles open dedicated tabs and keep their protocol. Run `cargo test --offline --manifest-path Gloamux/RDP/Cargo.toml` for the helper's unit tests: ZRLE tiles and the shared zlib stream, CopyRect, rectangle bounds, version and security negotiation, the VNC DES response, and the Apple sign-in block. Local protocol fixtures have also verified RDP certificate approval, CredSSP sign-in, pixels and keyboard and pointer events, plus VNC framebuffer and input over RFB.

For SSH interoperability checks, set `GLOAMUX_REMOTE_HOSTS` to a comma-separated list of `user@host[:port]` targets and `GLOAMUX_REMOTE_KEYS` to a folder with test private keys and a `known_hosts` file containing the verified server keys. Run `swift test --package-path Gloamux --filter RemoteHostTests`. The second target is also tested through the first as a jump host. Set `GLOAMUX_REMOTE_LOGIN_ONLY` to a comma-separated list of hosts whose restricted shells can only be checked for successful login.

The remote desktop engine uses [IronRDP](https://github.com/Devolutions/IronRDP). Its [MIT](Gloamux/RDP/licenses/ironrdp-MIT.txt) and [Apache 2.0](Gloamux/RDP/licenses/ironrdp-Apache-2.0.txt) notices ship with the app. [Cargo.lock](Gloamux/RDP/Cargo.lock) records the resolved Rust dependencies.

SwiftPM resolves dependencies using [Package.resolved](Gloamux/Package.resolved). Bundled Visual Studio Code theme color data is distributed with its [MIT notice](Gloamux/Sources/app/Resources/vscode-themes-license.txt). Workbench colors from MIT-licensed Marketplace themes are distributed with their [license notices](Gloamux/Sources/app/Resources/vscode-community-themes-licenses.txt). To change the bundled themes, edit the selection in [build-vscode-themes.py](Gloamux/scripts/build-vscode-themes.py) and run it with a local Visual Studio Code app and the downloaded `.vsix` packages. Linux distribution palettes are defined in `ThemeGallery.swift`; [THEME-INVENTORY.md](THEME-INVENTORY.md) records their sources. Gloamux's workspace layout and theme picker are native implementations. Xshell session import supports selected fields from compatible profiles. The MobaXterm reader (`MobaXtermImport` in `SessionImports.swift`) follows the field positions of MobaXterm's session export, which Mobatek does not document; it reads SSH (type 0) and SFTP (type 7) sessions and tolerates short field lists from older versions. Import files are decoded as UTF-16 or UTF-8 when marked or valid, then as Big5 (CP950), GB 18030, and Windows-1252. `SessionExport` writes `.gloamuxsessions` JSON (`SessionsFile`) and CSV; both leave out passwords and rewrite paths under the home folder as `~/…`.
