## 保護等級

這些等級是保護目標。下方儲存清單記錄 1.2.2 (build 5) 實作提供的保護，以及仍存在的缺口。

| 等級 | 意義 | 必要保護 |
|---|---|---|
| **S1 · 機密** | 能取得系統或其他機密的存取權。 | 以驗證式加密存放，金鑰絕不以明文離開 Gloamux。絕不寫進記錄檔、錄影、巨集、當機報告、匯出、同步、CLI 或 MCP。只在需要時留在記憶體，鎖定時清除。 |
| **S2 · 敏感內容** | 可能洩漏機密或私有基礎架構，但本身不能用來驗證。 | 預設加密存放，或由使用者明確設定。離開 App 前先遮蔽機密。分享前需要使用者明確操作。 |
| **I · 完整性關鍵** | 遭竄改會削弱安全性，例如把連線導向別處或核可某台主機。 | 以 Gloamux 持有的金鑰偵測竄改。拒絕或標示被修改的資料。 |
| **L · 低** | 與安全無關的偏好設定。 | 私有檔案權限。 |

## 目前的儲存方式

Gloamux 的工作檔案放在 `~/Library/Application Support/Gloamux`。資料夾權限為 `0700`，檔案以 `writePrivate` 寫成 `0600`。語言偏好存在 `UserDefaults`。

| 資料 | 位置 | 等級 | 目前保護 | 缺口 |
|---|---|---|---|---|
| 已存的登入資訊（密碼和金鑰密語） | `saved-sign-ins.json` | S1 | 每筆以 AES-GCM 加密，並以其 ID 作為關聯資料綁定；金鑰由 Secure Enclave P-256 金鑰協商經 HKDF-SHA256 衍生。檔案只存 Enclave 包裝過的金鑰代號，只能在這台 Mac 使用。不需解鎖，所以重新開機後連線仍可直接連上。連線可設定每次連線前要求 Touch ID 或 Mac 密碼。已存密碼清單要先通過 Touch ID 或 Mac 密碼才能打開，只在要求時顯示機密，複製的密碼若 60 秒內沒有其他複製，就會從剪貼簿清除。 | 任何以使用者身分執行的程序都能讀這個檔案，並請 Secure Enclave 重建金鑰，曝險程度和未受保護的鑰匙圈項目相同。項目清單沒有 MAC，所以項目可能被刪除或回滾。鎖定時不會清除。 |
| 加入密碼庫的密碼 | `password-vault.json` | S1 | 以 PBKDF2-HMAC-SHA256（210,000 次迭代）從主密碼衍生金鑰，每筆以 AES-GCM 加密。 | 項目 ID 沒有綁定為關聯資料，加密後的項目可在 ID 之間互換而不被察覺。沒有自動鎖定。PBKDF2 迭代次數低於 [OWASP 對 PBKDF2-HMAC-SHA256 建議的 600,000 次](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)，且 PBKDF2 不是記憶體困難（memory-hard）演算法。 |
| 主密碼與衍生金鑰 | 只在記憶體 | S1 | 手動鎖定會丟棄解開的金鑰。在相容的 Mac 上，Gloamux 會保留一份以 Secure Enclave 金鑰協商衍生金鑰加密的副本，並受目前的 Touch ID 登記保護。這份副本只在 App 執行期間存在。 | 閒置、睡眠、螢幕鎖定或 App 失去焦點時都不會鎖定。可選的工作區閒置鎖定（`workspace.lock-after-minutes`，預設關閉）只遮住終端，直到通過 Touch ID 或 Mac 密碼；它不會鎖定密碼庫，也不會清除記住的密碼。Swift 的 `String` 和 `SymmetricKey` 副本無法可靠歸零。 |
| 本次工作階段記住的密碼 | 記憶體中的 `CredentialVault.sessionPasswords` | S1 | 能登入的密碼或金鑰密語會立刻存進 `saved-sign-ins.json`，不論有沒有密碼庫。沒有 Secure Enclave 的 Mac 上，密碼庫解鎖時會存進密碼庫，否則等下次解鎖。用 Touch ID 從已鎖定的密碼庫讀出、只供一次連線用的項目也放在這裡。密碼庫鎖定時清除。 | 閒置或睡眠時不清除。分頁關閉後仍保留，直到密碼庫鎖定。 |
| 密碼、金鑰密語和跳板機密欄位 | `SessionTab` 的發布屬性 | S1 | 連線後與中斷時清除。 | 輸入期間值存在 SwiftUI 狀態中。可以接受，但要排除在畫面狀態還原和診斷資料之外。 |
| 私鑰檔 | `identityPath` 中的使用者路徑 | S1 | Gloamux 只存路徑。密語只用來載入一次。 | 解密後的金鑰在工作階段期間留在記憶體。現有產生器會在 `~/.ssh` 寫入 Ed25519 金鑰，可選擇密語。未設定密語時，磁碟上的私鑰沒有加密。 |
| Secure Enclave SSH 身分 | App 資料夾中的 `ssh-key-secure-enclave` | S1 | P-256 簽章金鑰留在 Secure Enclave 內，無法匯出。檔案只含 Enclave 加密的表示，只能在這台 Mac 使用。簽章不需要 Touch ID；0.10.0 版建立的金鑰每次啟動仍會詢問一次。 | 換新 Mac 時需要新金鑰，並在伺服器端重新登記公鑰。 |
| 連線目錄與轉發規則 | `sessions.json` | S2 與 I | 明文 JSON，`0600`。不含憑證。App 把轉發的監聽位址限制在回送介面。 | 主機名稱、使用者名稱、連接埠、代理、跳板和金鑰路徑會構成使用者基礎架構的地圖。明文會被複製到 Time Machine 和其他備份。被修改的主機、跳板項目或轉發規則可能把連線導向別處。 |
| 已知主機 | `known-hosts.json` | I | 明文 JSON，`0600`。金鑰改變會擋下連線。 | 沒有竄改偵測。以使用者身分執行的惡意程式可以加入受信任的金鑰，在不提示的情況下促成中間人連線。 |
| X11 轉發授權 | SSH shell 期間的記憶體 | S1 | Gloamux 傳給伺服器的是隨機替代 cookie，只有在檢查過通道設定後才換成真的。真正的 cookie 只交給本機 X 伺服器。 | 受信任轉發工作階段上的遠端程式，在 shell 關閉前都能使用本機 X11 顯示。 |
| RDP 和 VNC 端點 | 連線目錄 | S2 | 目錄記錄主機、連接埠、可選的 RDP 使用者名稱，以及已核可的 RDP 憑證指紋。 | 目錄檔沒有獨立的竄改偵測。 |
| RDP 和 VNC 密碼 | Gloamux 及其內附輔助程式的記憶體，記住時另存於 `saved-sign-ins.json` 或密碼庫 | S1 | 透過私有管道傳給輔助程式。RDP 會在登入前驗證伺服器憑證。開啟「記住密碼」後，成功登入的密碼會透過與 SSH 相同的憑證儲存機制保存。App 與輔助程式也會在連線和重新連線期間把憑證保留在記憶體。 | 傳統 VNC 驗證和桌面流量沒有傳輸加密。 |
| 快速指令 | `quick-commands.json` | S2 | 明文 JSON，`0600`。 | 使用者常把權杖、密碼或內部網址貼進指令。 |
| 終端回捲 | 記憶體，預設每個終端 5,000 行（1,000 至 50,000） | S2 | 除非開啟記錄檔或錄影，否則不會寫入磁碟。 | 輸出可能含有機密。搜尋、CLI 的 `tabs read`、記錄檔、錄影，以及使用者分享給代理的片段都從這裡讀取。 |
| 記錄檔與錄影 | 明文記錄檔和 asciicast 檔，`0600`，放在 `0700` 資料夾 | S2 | 只在使用者開啟記錄或錄影時寫入。寫入前會遮蔽可能的機密（私鑰區塊、存取權杖、`password=` 值）。錄影停止後在背景遮蔽並寫入；寫不進去的錄影會留在記憶體，直到按**重試**存好或 App 結束，結束前會先詢問是否捨棄。 | 遮蔽依靠樣式比對，會漏掉無法辨認的機密。檔案未加密，會被複製到備份。 |
| 代理存取與活動 | `agent-access.json`、`agent-activity.json` | I 與 S2 | 明文 JSON，`0600`。在使用者於 Gloamux 中開啟並允許連線之前，存取都是關閉的。 | 沒有竄改偵測。以使用者身分執行的程序可以允許連線或刪除紀錄項目。 |
| 剪貼簿 | 系統剪貼板 | S2 | Gloamux 在貼上時讀取。遠端程式透過 OSC 52 寫入會被拒絕，除非開啟 `terminal.allow-clipboard-writes`（預設關閉）。 | 開啟剪貼簿寫入後，遠端程式可以把機密放進共用剪貼板和通用剪貼板。選取即複製仍在規劃中。 |
| SFTP 下載 | 使用者選的資料夾，加上 `.gloamux-<UUID>.partial` | S2 | 失敗時刪除暫存檔。 | 暫存檔使用預設權限。下載的檔案由使用者負責，但暫存檔應為 `0600`。 |
| 設定備份 | 使用者選的 `.gloamuxconfig` 檔及其 `.sha256` | S1 與 S2 | 寫成 `0600`。原樣帶上以主密碼加密的 `password-vault.json`；主密碼、這台 Mac 記住的密碼和 Secure Enclave 金鑰都不包含在內。只有備份含密碼庫時，還原才會取代密碼庫，而且會先把目前的密碼庫複製到 `Backups/`。 | 備份的其他部分是明文。拿到檔案的人可以用密碼庫的 PBKDF2 成本離線猜測主密碼，所以密碼庫的強度取決於那組密碼。`.sha256` 檔只能偵測損壞，無法偵測蓄意修改。 |
| 外觀與版面 | `appearance.json`、`layout.json` | L | `0600`。 | 無。 |
| 語言 | `UserDefaults` | L | 系統預設值。 | 無。 |
| 更新偏好與上次檢查時間 | `UserDefaults`（`SUEnableAutomaticChecks`、`SULastCheckTime`） | L | 系統預設值。Sparkle 透過 HTTPS 從 GitHub 下載更新清單和 DMG，只安裝 EdDSA 簽章符合 `SUPublicEDKey` 的 DMG。請求的 User-Agent 包含 App 與 Sparkle 版本，GitHub 會收到請求和來源 IP。系統資訊蒐集預設關閉。更新清單和版本說明透過 HTTPS 取得，DMG 帶有 EdDSA 簽章。見 [Sparkle 設定文件](https://sparkle-project.org/documentation/customization/)。 | 版本是 ad hoc 簽署，沒有經過公證。簽署金鑰放在發布者的登入鑰匙圈；金鑰遺失時，使用者必須手動重新安裝。 |

### 其他發現

- `writePrivate` 以 `O_EXCL | O_NOFOLLOW` 建立 `0600` 暫存檔再改名就位，所以沒有任何檔案會被其他使用者讀到。資料夾建立時為 `0700`，但已存在、權限較寬的資料夾不會被修正。應在啟動時檢查資料夾權限。
- 密碼庫的 salt 使用 `UInt8.random(in:)`，在 Apple 平台上使用系統亂數產生器。應明確改用 `SecRandomCopyBytes` 或 `SymmetricKey(size:)`，讓審閱時看得出亂數來源。
- 密碼庫檔案沒有涵蓋整組項目、綁定版本的完整性檢查。能寫入檔案的攻擊者可以刪除或回滾個別項目。

## 建議設計

1. **密碼庫第 2 版。** 產生隨機 256 位元資料金鑰，用主密碼衍生的金鑰包裝，並可另用需要 Touch ID 的鑰匙圈項目包裝。使用 Argon2id；若不能接受新增相依套件，則用至少 600,000 次迭代的 PBKDF2-HMAC-SHA256。把每筆項目的 ID 綁定為 AES-GCM 關聯資料。為項目清單加上 MAC 和版本計數器。第一次解鎖時遷移第 1 版密碼庫。
2. **加密的工作區儲存。** 用從密碼庫資料金鑰衍生的金鑰加密 S2 檔案：連線目錄、快速指令、記錄檔、錄影、操作手冊和紀錄。只有在解鎖前就需要時才保留明文索引，且索引不含主機或使用者名稱。
3. **主機信任完整性。** 為 `known-hosts.json` 加上 HMAC，金鑰存在鑰匙圈。檢查失敗時視為不受信任的主機，並以清楚的警告重新詢問。
4. **鎖定政策。** 在可設定的閒置時間後、睡眠、螢幕鎖定和結束時鎖定。鎖定時清除本次記住的連線密碼。
5. **記憶體處理。** 盡量把機密放在 `Data` 或位元組緩衝區，用完後覆寫。不要把機密放進畫面狀態還原、復原堆疊或診斷資料。
6. **檔案處理。** 私有檔案已直接建立為 `0600`。啟動時檢查工作區資料夾為 `0700`。SFTP 暫存檔以 `0600` 建立。

## 驗證

以下是保護改進的驗證要求。密碼庫第 2 版、工作區加密和竄改防護仍待實作。

- 單元測試：密碼庫第 2 版往返、項目互換與回滾偵測、密碼錯誤、從第 1 版遷移，以及每種觸發條件下的鎖定。
- 針對 `known-hosts.json` 和連線目錄的竄改測試。
- 每次新增輸出管道的功能後，掃描記錄檔、錄影、當機輸出、CLI 輸出和 MCP 回應中是否出現測試機密。
- 手動確認未解鎖時無法讀取工作區檔案，且 Time Machine 副本不含明文 S1 或 S2 資料。

## 待決事項

- **2026-11-21 決定：密碼庫是選用的，且優先於每個連線的確認。** 沒有密碼庫時，能登入的密碼記在 `saved-sign-ins.json`，之後不需提示就能再次連線，重新開機後也一樣；開啟 **每次連線以 Touch ID 確認**（新連線預設開啟）的連線每次都會詢問。原先規劃建立密碼庫時搬入記住的密碼，並刪除 `saved-sign-ins.json`。下方修訂決定已取代這個儲存方式。密碼庫解鎖期間，連線會略過每次連線確認。
- **2026-11-21 決定（修訂）：密碼庫鎖定時恢復每個連線的確認，且保留 `saved-sign-ins.json`。** 建立密碼庫不再把記住的密碼搬進去。密碼庫鎖定時，設定為每次連線都詢問的連線會詢問（Touch ID 或 Mac 密碼），其他連線則用這台 Mac 上的副本連線，所以鎖定密碼庫不會保護這些副本。只存在已鎖定密碼庫中的密碼，會以 Touch ID 為該次連線讀出，密碼庫維持鎖定。
