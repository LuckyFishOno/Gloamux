## Gloamux 1.8.3 (build 22)：空白錄影與 Runbook 選取（2026 年 11 月 27 日）

- 錄影視窗在沒有項目時仍保留側欄清單，讓清單撐滿分割視窗的高度。標題固定在上方，右側只顯示一個「沒有錄影」提示，不再要求從空清單選取項目。
- Runbooks 同樣保留清單，以疊加方式顯示空白提示。新增與匯入改為回傳和目錄列舉相同、已解析符號連結並正規化的 URL。回歸測試重現同一檔案建立時是 `/var/...`、清單中卻是 `/private/var/...`；選取值仍在，但無法通過右側的清單成員檢查。修正前，三輪新增／刪除皆失敗；統一路徑後通過。
- 新增託管視圖測試，涵蓋空清單轉為有內容，以及實際帶主題的 ToolWindow 包裝；保留既有空白與有內容的排版案例。聚焦測試 8 項通過；完整 Swift **620 項，612 通過、8 跳過、0 失敗**。封裝、深度嚴格簽章驗證與 9/9 自我檢查通過。使用獨立識別碼 `local.gloamux.windowcheck20261127` 的封裝版，確認空白錄影標題位於頂端、右側僅一個空白提示；點擊新增 Runbook 後，新增列立即選取並顯示內容。測試版已關閉。依擁有者要求以 `release.sh build --skip-tests` 發布為 1.8.3 (build 22)；上述測試已在相同原始碼上先跑過。紀錄位於 `/tmp/gloamux-tool-windows-*.log` 與 `/tmp/gloamux-runbook-paths.log`。未重跑全 App 壓力測試或另跑 Rust 測試，Rust 原始碼未變更。

## Gloamux 1.8.2 (build 21)：空的錄影與 Runbook 視窗（2026 年 11 月 27 日）

- **改了什麼。** 沒有任何項目時，**錄影** 和 **Runbook** 視窗會把標題列和空狀態畫在視窗下半部，上方留白。分割檢視裡沒有任何子視圖能長高，所以分割檢視縮成內容的高度，AppKit 把它放在視窗底部。現在清單欄和空狀態都會填滿視窗高度。
- **單元測試。** `ToolWindowLayoutTests`（3 個）以預設大小放置每個視窗，確認分割檢視填滿視窗、標題列在頂端：空的錄影、空的 Runbook，以及有一個檔案的 Runbook。修正前兩個空的情況會失敗。
- **打包後的 App、改名副本、獨立工作區。** 空的錄影和 Runbook 視窗標題列在頂端、空狀態置中；已發布的 1.8.1 副本仍畫在底部。按 **新增 Runbook** 後，清單和 Runbook 內容填滿視窗。
- **未檢查。** 沒有在打包後的 App 開啟列有影片的錄影視窗；清單有內容時，修改前就已填滿高度。**新增 Runbook** 會列出新檔案但不會選取它，1.8.1 也一樣，這次沒有修改。

## Gloamux 1.8.1 (build 20)：「已存密碼」在無障礙工具讀取時保持回應（2026 年 11 月 27 日）

- **改了什麼。** 沒有已存密碼時，**已存密碼** 面板在清單載入後會顯示 `ContentUnavailableView`。這個 view 插入已經開啟的面板後，只要 VoiceOver、視窗管理工具或自動化工具讀取視窗，SwiftUI 的無障礙更新就會在 attribute graph 裡無限循環：主執行緒一直滿載，`gloamux` 對 App 的請求也得不到回應。面板的空狀態改成一般的圖示、標題與說明，文字不變。這個問題從 1.6 (build 17) 就存在。
- **如何找到並縮小範圍。** 用一個不需 Touch ID 就能開啟面板、並以 `AXUIElement` 客戶端讀取的診斷版：同一個 view 在面板第一個畫面就存在、普通文字，或稍後插入的自製圖示與文字，都不會卡；稍後插入的 `ContentUnavailableView` 會卡，放在一般堆疊或 `ZStack` 都一樣。同一個 view 放在主視窗的連線歷史不會卡。單元測試裡放進 `NSWindow` 的 view 從未出現循環，所以回歸測試 `SavedSignInsViewTests` 確保面板原始碼不再使用這個 view。
- **其他面板，同一個客戶端。** 編輯連線、重新命名、從歷史貼上，以及設定視窗：沒有循環。其他面板都沒有使用 `ContentUnavailableView`。
- **使用 `ContentUnavailableView` 的視窗，已發布的 1.8.1，空的工作區。** 錄影、Runbook、探索主機、主機金鑰（兩個分頁，「紀錄」分頁是在視窗開著時切換的），以及經典版面的連線歷史視窗，都顯示了各自的空狀態；每開一個就讓客戶端讀取整個 App 兩次，沒有循環，也沒有卡住。
- **打包後的 App、改名副本、獨立工作區。** 通過 Touch ID 開啟 **已存密碼** 後，連續三次讀取整棵無障礙樹，每次都在 0.05 秒內完成，AttributeGraph 沒有回報循環，App 約占 5% CPU，`gloamux tabs list` 立即回應。修正前，1.6 和 1.7 的副本做同樣步驟會卡死。

## Gloamux 1.8 (build 19)：視窗錄影的歷史紀錄（2026 年 11 月 27 日）

- **改了什麼。** `videos.json` 改成歷史紀錄：清單上的影片檔案不見時，會以 `exists` false 留在清單上，直到 **從清單移除**、**移到垃圾桶**（此時只拿掉紀錄）、`gloamux videos forget`，或 **清除歷史紀錄** / `gloamux videos clear`（檔案都保留）。Gloamux 回到前景時清單會重新檢查。舊的工作區 `videos` 資料夾會加進清單一次。每列顯示第一格縮圖、去掉開始時間的名稱，開始時間放在下一行；播放器底列顯示資料夾。
- **單元測試。** `VideoRecordingTests`（18 個）：原本的 16 個，加上檔案不見時保留並標示、移除時不出錯、忘記與清除都保留檔案、舊資料夾只列一次，以及名稱去掉開始時間；命令列測試涵蓋 `exists`、`forget`、`clear`，以及匯出不存在的檔案會被拒絕。
- **打包後的 App、改名副本、獨立工作區。** 錄影視窗列出兩支示範影片和一支已刪除的影片；已刪除的那支顯示 **找不到檔案**、路徑和 **從清單移除**；在 Finder 把檔案移到垃圾桶後重新載入會標示出來；縮圖、名稱、日期和資料夾路徑都正確顯示；`gloamux videos list` 回報 `exists`。
- **未檢查。** 沒有在打包後的 App 實際按 **清除歷史紀錄** 和 **從清單移除**；由單元測試涵蓋。

## Gloamux 1.7 (build 18)：視窗錄影（2026 年 11 月 27 日）

- **功能。** 用 ScreenCaptureKit 和 `AVAssetWriter` 把整個工作區視窗錄成不含聲音的 H.264 MP4 或 MOV，可從工具列、**終端 › 錄製視窗影片**（⇧⌘R）、指令面板或 `gloamux videos start` 開始。影片預設存在下載項目（`video.folder`），透過 `videos.json` 列在 **終端 › 錄影**，權限 0600。
- **單元測試。** `VideoRecordingTests`（16 項）：暫停時間軸、上限與檔名、包含存放位置的設定、兩種格式的寫入（剪掉暫停、2.5 秒、沒有音軌、0600）、沒錄到內容時不留檔、工作區資料夾和其他資料夾的當機救回、清單忽略其他檔案並拿掉已刪除的影片、錄影視窗建出播放器，以及 `gloamux videos`（同意說明、`--yes`、`--window`、匯出、刪除、設定）。
- **打包 App、改名副本、獨立工作區、已給螢幕錄製權限。** 開工作表時計時停住（停在 0:56）；縮到 Dock 會暫停；調整視窗大小持續錄影；強制結束後留下的檔案在下次啟動時取好檔名，是剪掉暫停的 56.0 秒 MP4；60 fps 的 MOV（11.46 秒、668 格、Rec.709）看得清終端文字；從工具列停止會出現 **錄影已儲存**，按 **顯示** 開啟可播放的錄影視窗；關閉視窗會存好進行中的錄影；App 層級的警告框開著時計時照走（11 到 16 秒），那段 24.7 秒的影片可完整解碼。
- **檢查中發現並修正。** 錄影視窗顯示影片時，SwiftUI 的 `VideoPlayer` 會讓打包的正式版 App 中止（debug 測試看不出來），改用 AppKit 的 `AVPlayerView`。計時器在 App 層級的警告框開著時會停，改成在 common run loop 模式執行。分段寫入的檔案在格與格時間不規則時寫入失敗（-11800/-16341），關掉 frame reordering 後正常。
- **未檢查。** 重新簽署後要再給一次螢幕錄製權限，所以打包 App 實際存到下載項目的流程由單元測試涵蓋。有輔助使用程式讀取視窗時打開 **已存密碼** 會讓 App 卡住；1.6 也一樣，1.7 未修正。

## Gloamux 1.7 (build 18)：工具列提示，以及檔案傳輸與 Session Log 的版面（2026 年 11 月 27 日）

以 `9670fcc`（1.6 build 17）為基礎，於 1.7 (build 18) 發布。

- **使用者回報。** 預設版面中，瀏覽器、檔案、快速指令和色彩主題四個按鈕共用一個工具列項目。AppKit 每個項目只顯示一個提示，所以指到任何一個都顯示「Browser」，在它們之間移動時提示也不會淡出換成下一個。現在每個按鈕各自是一個工具列項目。
- **單元測試。** `WorkspaceToolbarTests.testEachSidebarButtonHasItsOwnToolbarItemAndTooltip` 把工作區放進有標題列的視窗，確認每個按鈕的提示只屬於一個項目，而且該項目不顯示其他提示。把四個按鈕放回同一個項目時，檔案、快速指令和色彩主題三項會失敗。
- **使用者回報：檔案傳輸和 Session Log 跑到面板底下。** 右側面板最多可以占到只剩 340 點（終端的最小寬度），但兩個檔案窗格約需 700 點，Session Log 的清單和細節也約需 700 點，所以內容溢出到連線樹上、被瀏覽器蓋住。現在中間會依模式保留需要的寬度（`DesktopView.centerMinimum`）：終端 340、兩個檔案窗格加箭頭 734、Session Log 520；右側面板會讓出空間，連線樹仍保有 200 點的最小寬度。中間區域會裁切，不會畫到側欄上。兩個檔案窗格永遠等寬，箭頭固定在正中間（`CenteredColumns`）。Session Log 的清單最窄可縮到 180 點，細節 320 點；再窄時清單和連線輪流顯示，連線標題列會把狀態和 **下載紀錄** 換到名稱下方，篩選改成選單。
- **單元測試。** `SidebarLayoutTests.testTheCenterKeepsRoomForItsColumnsInEveryMode`（1,268 點寬視窗、640 點右側面板時各模式保留的寬度，以及 1,040 點寬視窗時連線樹的最小寬度）和 `testTheTransferArrowsStayCentered`（四種寬度下窗格等寬、箭頭置中）。

## Gloamux 1.6 (build 17)：瀏覽器面板、測試腳本，以及改名副本寫入的設定（2026 年 11 月 27 日）

以 `f72a8d5`（1.5 build 16）為基礎，連同下一節的 kitty 圖片等修改一起發布。

- **過程中的設計調整。** 先做出並驗證了已存的 **網頁** 連線類型（含 **透過 SSH**），之後依擁有者要求移除，網頁只在瀏覽器面板開啟。面板的網頁改成標題列上的分頁，畫法和工作階段分頁相同；右邊每個面板共用一個寬度，可以拖曳到只留給終端 340 點。連線樹選單的 **從 sftp 指令新增工作階段** 已移除，指令面板和直接貼上指令仍可使用。
- **單元測試。** `WebPageTests`（8 個：輸入的網址和 Google 搜尋、被拒絕的通訊協定和帳號密碼、下載檔名、縮放上下限、網頁分頁和 20 頁上限、憑證上限、User-Agent、網頁不是連線類型，以及每個 `gloamux web` 操作和錯誤輸入）和 `BrowserPanelPageTests`（2 個：本機伺服器的網頁用 Safari 的 User-Agent 載入，再開第二頁、上一頁和下一頁；HTTP Basic 登入在同一網站會沿用，**清除網站資料** 後會再要求登入）。`SidebarLayoutTests` 檢查右側共用寬度。
- **檢查程式時發現清除後仍保留登入。** **清除網站資料** 用 `removeData(ofTypes:)` 清空資料，但 WebKit 仍用先前的 HTTP 登入回應網站；修正前，新測試就是這樣失敗。現在面板會把網頁換到新的網站資料並重新開啟每一頁，選單和 `gloamux web clear-data` 都一樣。隱藏面板時會暫停聲音和影片。
- **Swift 測試。** 592 個：584 個通過、8 個略過（需要外部輸入的遠端主機和 Xshell 範例檢查）、0 個失敗。Rust 遠端桌面引擎：18 個通過。兩組測試會在發布 commit 上由 `release.sh build` 再跑一次。
- **改名副本寫入的設定。** App 關閉時，從改名測試副本執行的 `gloamux settings set` 和 `gloamux config import` 會寫入已安裝 App 的網域 `local.gloamux.desktop`，因為命令列工具不知道自己屬於哪個 App。現在它寫入所在 App 的網域，所以從副本執行 `settings set terminal.scrollback 50000` 只改到 `local.gloamux.uitest`，已安裝 App 的設定在下面每次執行中都完全沒變。
- **和 `--workspace` 一起的說明。** 新的功能檢查發現 `gloamux web --help --workspace PATH` 會把 `--help` 當成不明選項拒絕。現在每個指令在這種寫法下也會顯示說明。新測試：`CLICatalogTests.testHelpIsRecognizedNextToAWorkspace`。需要執行中 App 的指令，現在提示時不再只提到分頁，例如 `gloamux web`。
- **功能檢查。** 新的 `feature-check.py` 對改名副本、拋棄式工作區、只在 127.0.0.1 且只接受金鑰的拋棄式 `sshd`，以及本機網頁伺服器，執行每一組 `gloamux` 指令的一項實際操作。第一次 50 項通過 47 項；三項失敗都是腳本本身的問題：用空白文字執行 `tabs run`、沒有快速鍵設定就叫出下拉視窗，以及用 macOS 內建 LibreSSL 產生的 EC 金鑰憑證，TLS 握手在網頁詢問前就失敗。單獨重測時，App 對 RSA 憑證會詢問、拒絕錯誤的指紋、用正確指紋開啟網頁，也能拒絕另一頁。修正腳本後：50 項全部通過。
- **壓力測試。** 對改名副本完整執行 `stress-test.py --app`，16 個階段全部通過。20 個本機分頁和 10 個 SSH 分頁各印出 1,000,000 行，約每秒 691,000 行，記憶體峰值 712 MB，關閉後 157 MB。新的寬字元階段在 1.2 秒內印出 200,000 行中日韓文字和 500 張 kitty 圖片。瀏覽器面板開了 41 頁、保留 20 頁，2.7 秒全部載入，3.8 秒完成 70 次導覽，使用 20 個 WebKit 程序共 532 MB，關閉網頁後沒有留下 WebKit 程序。終端效能測試的中日韓文字為 71.4 MB/s。
- **打包後的 App。** `package-app.sh` 和 `codesign --verify --deep --strict` 通過。在改名的測試副本（`local.gloamux.uitest`）和獨立的工作區中，用 `gloamux web` 操作：`show` 和 `open` 在面板載入本機 `http.server` 的網頁，沒有新增分頁；網頁的 `navigator.userAgent` 回報 `Version/27.2 Safari/605.1.15`；`go`、`back`、`select`、`zoom 150`、`close`、`hide` 和 `clear-data` 正常；`open "gloamux terminal"` 載入 Google 搜尋結果；`ftp://` 和 `file://` 網址及不明的網頁 ID 以結束代碼 2 拒絕；`sessions add-other ... web` 被拒絕。擁有者在測試副本看過網頁分頁，確認沒問題。正在播放聲音的網頁在 `hide` 關閉面板時收到 `pause`；會設定 Cookie 的網頁重新載入後仍找得到 Cookie，`clear-data` 後則找不到，且網頁會自己重新開啟。
- 未檢查：對真實設備的憑證核可和登入視窗、點擊下載，以及透過 **檢查更新** 安裝更新。

## Gloamux 1.6 (build 17)：kitty 圖片、像素大小、更快的中日韓文字、重新連上後的畫面，以及編輯過的桌面連線（2026 年 11 月 26 日）

以 `f72a8d5`（1.5 build 16）為基礎的工作目錄，和上方的瀏覽器面板一起在 1.6 發布。
